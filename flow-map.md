# Ainfluencer flow map

This is the list of user-facing flows (topics) in Ainfluencer, built from the production code. It's the outline for the support knowledge base: each topic below will get its own document later. Nothing here is a full explanation yet; each row says what the flow covers, where users meet it, and which backend parts and automations it involves.

Each topic has a stable ID (for example `OFR-03`) so documents, tickets and the support assistant can refer to it.

## How "live" was decided

Only code a real user can reach is included:

- **Web**: a page counts if it's in the active route table and reachable from the app entry. An API call counts only if a reachable component actually calls it.
- **Mobile**: a screen counts if it's registered *and* something navigates to it (button, deep link or push notification). An API call counts only if a reachable screen uses it.
- **Backend**: an endpoint counts only if the web or mobile app calls it, a third party or the chat service calls it (webhooks), or a scheduled job runs it.
- **Chat**: a socket event counts only if both the client and the chat gateway handle it.

**Core API:** of 1,148 backend routes, 365 are called by the apps and 33 are webhooks or payment/OAuth returns. 188 are admin-only, 88 belong to other in-house apps, 61 are website pages, and **413 are called by nothing**.

**Affiliate API:** of 895 routes, 479 are called by the seller app, the affiliate app, the buyer site or core, and 24 are webhooks or OAuth returns. 180 are admin-only, 35 are infrastructure, and **177 are called by nothing**.

The dropped code is listed in [_map-evidence/excluded-dead-code.md](_map-evidence/excluded-dead-code.md).

## Who's who

- **Brand**: uses the **web app** (app.ainfluencer.com). Creates campaigns, finds influencers, negotiates and pays for offers, approves content. Can have **team members**.
- **Influencer**: uses the **mobile app**. Connects social accounts, browses campaigns, sends offers, delivers content, gets paid. An influencer who logs into the web app is sent to a "download the app" page.
- **Admin**: Ainfluencer staff in the admin panel. Approves campaigns and accounts, edits offers, pays payouts by hand. Admin actions show up in many flows below.
- **System**: scheduled jobs and webhooks that change state without anyone clicking.

The **affiliate platform** is a separate product with its own backend, apps and logins, connected to Ainfluencer by single sign-on:

- **Seller**: a brand or store owner on the affiliate platform (**seller.ainfluencer.com**). Connects an Amazon or Shopify store, sets commissions, partners with affiliates, and is **charged commission by card**. An Ainfluencer brand who opens the affiliate area becomes a seller.
- **Affiliate**: a creator on the affiliate platform (**affiliate.ainfluencer.com**). Partners with sellers, makes tracked product links and storefronts, and is **paid through Stripe Connect**. An Ainfluencer influencer who opens the affiliate area becomes an affiliate.
- **Buyer**: a shopper who clicks an affiliate's link and lands on the public product page or storefront. The purchase itself happens on Amazon or Shopify.

The same email can have both a seller and an affiliate profile; users switch between them from the user menu.

The main lifecycle that most tickets touch:

```
Brand creates campaign (CMP-01) → admin approves (CMP-02) → influencer finds it or is invited (MKT-01, DSC-03)
→ influencer sends offer (OFR-01) → negotiation (OFR-02) → brand pays, money held in escrow (OFR-03)
→ influencer posts and submits link (PUB-01) → brand/admin approves (PUB-02)
→ money released to influencer wallet (PUB-03); without approval the brand is refunded automatically
→ influencer requests payout, admin pays by hand minus the 20% fee (PAY-04)
```

The affiliate lifecycle runs on the affiliate platform, with different money rules:

```
Seller connects Amazon/Shopify store and a card (AFS-02, AFS-10) → sets commissions (AFS-03)
→ seller invites or affiliate applies; approved request = contract (AFS-06, AFA-04)
→ affiliate makes tracked links, storefront, coupons (AFA-05, AFA-06) → shopper clicks and buys on Amazon/Shopify (AFB-01)
→ sales come in through Amazon reports / Shopify pixel → after 35 days the seller's card is charged the commission
→ affiliate receives it minus the platform fee through Stripe Connect (AFS-10, AFA-08)
```

An Ainfluencer brand can also create an "affiliate campaign" inside the Ainfluencer web app; it is stored on the affiliate platform and influencers join it from the mobile app (CMP-04, MKT-03, AFX-02).

In the tables below:
- **Where** lists web URLs (`/…`) and mobile screens (UPPER_CASE).

- **Notes** holds things support should know: gaps, known bugs, and anything that behaves differently from what users expect.

## Two payment systems in the core API

The core backend has a **current** payment system (orders, three wallets per user, `finance/*` endpoints) and a **legacy** one (transactions, checkout requests). Both apps use the current one. The legacy one still holds history from before August 2025 and is still used by a few paths (PayPal returns, legacy revisions, the old wallet history). When a balance or history looks wrong, check whether the money is in the legacy records.
